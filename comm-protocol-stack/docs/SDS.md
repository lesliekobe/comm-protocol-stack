## 1. 概述

### 1.1 项目背景

在嵌入式开发、工业控制、通信设备等领域，经常需要设计私有通信协议。现有方案存在：
- 依赖外部库，增加系统复杂度
- 代码臃肿，不适合资源受限环境
- 缺乏完整错误处理和状态管理

本项目提供一套**轻量级、零依赖、可移植**的纯C协议栈实现。

### 1.2 设计目标

| 目标 | 描述 |
|------|------|
| 轻量级 | 核心代码 < 5000行，无外部依赖 |
| 可移植 | 支持 Linux / RTOS /裸机 (STM32/ESP32等) |
| 完整功能 | 封包、解包、状态机、CRC、会话管理 |
| 易集成 | 统一接口，分层清晰 |

### 1.3 应用场景

- 工业自动化控制 (PLC通信)
- 嵌入式设备间串口/网络通信
- 物联网传感器数据采集
- 自定义私有协议开发

## 3. 协议格式设计

### 3.1 帧结构

```
字节偏移:  0      1      2      3      4      5      6      7     ...    N-3   N-2   N-1
           ┌──────┬──────┬──────┬──────┬──────┬──────┬────────────┬──────┬──────┐
字段:       │ 帧头  │ 帧头  │ 长度  │ 长度  │ 地址  │ 命令码    │ 数据域       │ 校验  │ 校验  │ 帧尾  │ 帧尾  │
           │ 0xAA │ 0xBB  │ 高字节│ 低字节│      │         │ N字节        │ 高字节│ 低字节│ 0xCC  │ 0xDD  │
           └──────┴──────┴──────┴──────┴──────┴──────┴────────────┴──────┴──────┴──────┴──────┘
```

### 3.2 字段定义

| 字段 | 长度 | 字节序 | 取值范围 | 说明 |
|------|------|--------|----------|------|
| 帧头 | 2B | - | 0xAA 0xBB | 固定帧同步标识 |
| 长度 | 2B | Big-Endian | 8-1027 | 整个帧不含头尾的长度 |
| 地址 | 1B | - | 0x00-0xFF | 设备从机地址，0x00为广播 |
| 命令码 | 1B | - | 0x01-0xFF | 功能码定义 |
| 数据域 | N | - | 0-1024 | 业务数据，变长 |
| 校验 | 2B | Big-Endian | CRC16 | 从长度到数据域的校验 |
| 帧尾 | 2B | - | 0xCC 0xDD | 固定帧结束标识 |

### 3.3 命令码定义

| 命令 | 值 | 方向 | 说明 |
|------|-----|------|------|
| READ | 0x01 | Master→Slave | 读数据/寄存器 |
| WRITE | 0x02 | Master→Slave | 写数据/寄存器 |
| REPORT | 0x03 | Slave→Master | 主动上报 |
| HEARTBEAT | 0x04 | 双向 | 心跳保活 |
| ACK | 0x05 | 双向 | 应答确认 |
| NACK | 0x06 | 双向 | 应答否定 |
| RESET | 0x07 | Master→Slave | 设备复位 |
| UPDATE | 0x08 | Master→Slave | 固件升级 |
| ERROR | 0xFF | Slave→Master | 错误响应 |

### 3.4 错误码定义

| 错误 | 值 | 说明 |
|------|-----|------|
| ERR_NONE | 0x00 | 无错误 |
| ERR_CRC | 0x01 | CRC校验失败 |
| ERR_LEN | 0x02 | 长度超出范围 |
| ERR_ADDR | 0x03 | 地址无效 |
| ERR_CMD | 0x04 | 命令码不支持 |
| ERR_FRAME | 0x05 | 帧格式错误 |
| ERR_TIMEOUT | 0x06 | 通信超时 |
| ERR_OVERFLOW | 0x07 | 缓冲区溢出 |
| ERR_BUSY | 0x08 | 设备忙 |
| ERR_PARAM | 0x09 | 参数错误 |

## 4. 核心组件设计

### 4.1 环形缓冲区 (RingBuffer)

**设计目的：** 解决流式字节的粘包、半包问题

**数据结构：**
```c
typedef struct {
    uint8_t *buffer;      // 缓冲区起始
    uint16_t capacity;   // 容量（2的幂次）
    uint16_t read_pos;   // 读指针
    uint16_t write_pos;  // 写指针
} ringbuffer_t;
```

**设计要点：**
- 读写指针分离，写推进读
- 容量自动取整到2的幂次，便于取模运算
- 支持环绕操作
- 满时拒绝写入，防止覆盖

### 4.2 CRC校验

**支持算法：**

| 算法 | 多项式 | 应用场景 |
|------|--------|----------|
| CRC16-Modbus | 0x8005 | 默认协议校验 |
| CRC16-CCITT | 0x1021 | XModem协议 |
| CRC32-MPEG2 | 0x04C11DB7 | 数据校验 |
| CRC8-Dallas | 0x31 | 1-Wire总线 |
| Sum8/Sum16 | - | 简单校验 |

### 4.3 解包状态机

**状态定义：**
```c
typedef enum {
    WAIT_HEAD1,    // 等待帧头0xAA
    WAIT_HEAD2,    // 等待帧头0xBB
    WAIT_LEN1,     // 等待长度高字节
    WAIT_LEN2,     // 等待长度低字节
    WAIT_ADDR,     // 等待地址
    WAIT_CMD,      // 等待命令码
    WAIT_DATA,     // 等待数据域
    WAIT_CRC1,     // 等待CRC高字节
    WAIT_CRC2,     // 等待CRC低字节
    WAIT_TAIL1,    // 等待帧尾0xCC
    WAIT_TAIL2,    // 等待帧尾0xDD
    COMPLETE,      // 完整帧
    ERROR          // 错误
} parser_state_t;
```

**状态流转图：**
```
                         ┌────────────────────────────────────────┐
                         │                                        │
                         ▼                                        │
    ┌─────────┐   ┌────────────┐   ┌──────────┐   ┌──────────┐   │
    │WAIT_HEAD│──►│WAIT_HEAD2  │──►│WAIT_LEN1 │──►│WAIT_LEN2 │   │
    └─────────┘   └────────────┘   └──────────┘   └──────────┘   │
                           │              │                       │
                           │错误          │                       │
                           ▼              ▼                       │
                    ┌──────────┐   ┌──────────┐                   │
                    │  ERROR   │◄──│WAIT_ADDR │◄──┐                │
                    └──────────┘   └──────────┘   │                │
                           │              │        │                │
                           │重同步        │        │                │
                           ▼              ▼        ▼                │
    ┌─────────┐   ┌──────────┐   ┌──────────┐   ┌──────────┐   ┌────────────┐
    │WAIT_HEAD│◄──│WAIT_DATA │◄──│WAIT_CMD  │◄──│ WAIT_    │◄──│ WAIT_      │
    │   1     │   │          │   │          │   │  TAIL2   │   │  TAIL1     │
    └─────────┘   └──────────┘   └──────────┘   └──────────┘   └────────────┘
                           │                           │
                           │                           │正确
                           ▼                           ▼
                    ┌──────────┐               ┌────────────┐
                    │  ERROR   │               │ COMPLETE   │
                    └──────────┘               └────────────┘
```

### 4.4 会话管理

**会话状态：**
```c
typedef enum {
    SESSION_STATE_IDLE,      // 空闲
    SESSION_STATE_CONNECTED,  // 已连接
    SESSION_STATE_BUSY,       // 等待应答
    SESSION_STATE_TIMEOUT,    // 超时
    SESSION_STATE_ERROR       // 错误
} session_state_t;
```

**管理机制：**
- 发送数据后启动超时计时
- 收到ACK清除等待状态
- 超时后触发重传（可配置次数）
- 心跳保活检测设备在线状态

## 8. 错误处理

### 8.1 错误分类

| 类别 | 错误 | 处理策略 |
|------|------|----------|
| 帧格式错误 | 帧头/帧尾错、长度超限 | 丢弃，重同步 |
| 校验错误 | CRC错误 | 丢弃，记录日志 |
| 通信错误 | 超时、断连 | 重传、重连 |
| 资源错误 | 缓冲区满 | 丢弃最旧数据 |

### 8.2 恢复机制

1. **帧同步恢复：** 检测到帧头0xAA后，等待0xBB；错误则继续搜帧头
2. **超时重传：** 默认3次，间隔500ms
3. **断线重连：** 检测断连后，自动重连（需用户实现）

## 9. 移植指南

### 9.1 必需实现

1. **传输层接口：**
   - `transport_send_t`：发送N字节
   - `transport_recv_t`：接收N字节

2. **硬件初始化：**
   - UART初始化（波特率、数据位、校验位）
   - Socket创建/连接

### 9.2 可选扩展

1. **多会话管理：** 扩展session_t支持多设备
2. **加密传输：** 在封包后、发送前加密
3. **日志系统：** 集成调试日志
