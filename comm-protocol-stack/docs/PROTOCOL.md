# 协议规格书
# Protocol Specification

**版本：** v1.0.0
**协议名称：** CommProto v1.0

---

## 1. 协议概述

本协议是面向嵌入式系统和工业控制的私有通信协议，采用固定帧头帧尾 + 变长数据域的方案，支持广播、多设备通信、心跳保活和ACK应答机制。

---

## 2. 帧格式

### 2.1 完整帧结构

```
┌────────┬────────┬────────┬────────┬────────┬─────────────────┬────────┬────────┐
│  帧头   │  帧头   │  长度   │  长度   │ 地址   │ 命令码  │ 数据域(N字节)      │ CRC16  │  帧尾   │  帧尾   │
│  1字节  │  1字节  │ 高字节  │ 低字节  │ 1字节  │  1字节  │                    │ 2字节  │  1字节  │  1字节  │
│  0xAA  │  0xBB  │        │        │        │         │                    │        │  0xCC  │  0xDD  │
└────────┴────────┴────────┴────────┴────────┴────────┴─────────────────┴────────┴────────┘
         ▲                                                    ▲
         │                                                    │
    固定标识                                              可变校验
```

### 2.2 字段说明

| 偏移 | 字段 | 长度 | 字节序 | 说明 |
|------|------|------|--------|------|
| 0 | 帧头1 | 1B | - | 0xAA，帧同步 |
| 1 | 帧头2 | 1B | - | 0xBB，帧同步 |
| 2 | 长度高 | 1B | Big-Endian | 长度 = 地址 + 命令码 + 数据域 + CRC |
| 3 | 长度低 | 1B | Big-Endian | 同上 |
| 4 | 地址 | 1B | - | 0x00=广播，0x01-0xFF=从机地址 |
| 5 | 命令码 | 1B | - | 功能码 |
| 6 ~ 6+N-1 | 数据域 | 0-1024B | - | 业务数据 |
| 6+N ~ 7+N | CRC高 | 1B | Big-Endian | CRC16校验（长度到数据域） |
| 8+N | CRC低 | 1B | Big-Endian | 同上 |
| 9+N | 帧尾1 | 1B | - | 0xCC |
| 10+N | 帧尾2 | 1B | - | 0xDD |

**最小帧长：** 11字节（N=0，无数据域）
**最大帧长：** 1035字节（N=1024）

## 3. 帧格式示例

### 3.1 无数据帧示例

**心跳帧（无数据）：**
```
AA BB 00 06 02 04 7A 85 CC DD
│  │  ──  ─  ─  ─  ────  ─  ─
│  │   │   │  │  │   │    │  │
│  │   │   │  │  │   │    │  帧尾2=DD
│  │   │   │  │  │   │    帧尾1=CC
│  │   │   │  │  │   CRC低=85
│  │   │   │  │  │  CRC高=7A
│  │   │   │  │  数据(0字节)
│  │   │   │  命令=04(心跳)
│  │   │   地址=02
│  │  长度=06(地址+命令+CRC=1+1+2=4，+2=6? 不，含头尾吗？)
│  等等，让我重新算：不含头尾的字节：地址1+命令1+CRC2=4 → 帧头后到CRC前 = 长度字段的值
│  帧头(2) + 长度(2) + 4 + 帧尾(2) = 10字节
│  实际：00 06 = 长度值 = 6 = 地址+命令+CRC = 1+1+2
│  帧结构：AA BB [00 06] 02 04 [7A 85] CC DD
│            ↑长度=6     ↑数据 CRC      ↑帧尾
```

### 3.2 带数据帧示例

**读寄存器：**
```
发送：AA BB 00 09 02 01 00 10 xx xx CC DD
              ↑长度=9 = 1(地址)+1(命令)+2(数据)+2(CRC) = 6? 不对
              应该是：地址1 + 命令1 + 数据2 + CRC2 = 6... 
              但这里长度字段是 00 09 = 9
              00 09 = 9 = 1(地址)+1(命令)+2(数据)+2(CRC)+? 
              让我看：AA BB | 00 09 | 02 | 01 | 00 10 | CRC | CC DD
                      2B     2B      1B    1B     2B      2B    2B
              实际数据：00 10（2字节）
              CRC：xx xx
              长度00 09 = 从地址到CRC前的字节数 = 1+1+2+2 = 6? 不对
              重新理解：长度字段 = 从"地址"到"CRC前"的字节数 = 1+1+2 = 4? 
              或者是：从长度字段后面到帧尾前的所有字节？
```

**正确理解：**
- 长度字段 = 帧头后所有字节（不含帧头帧尾） = 地址 + 命令 + 数据 + CRC = 6
- 但 00 09 = 9 ≠ 6

让我重新分析示例帧：
```
AA BB 00 09 02 01 00 10 xx xx CC DD
   帧头  长度   |命令  |数据| CRC  帧尾
           │
           9 = 地址1 + 命令1 + 数据2 + CRC2 = 6? 
           实际上：9 = 从长度字节后到CRC前的所有字节？
           = 地址1 + 命令1 + 数据2 = 4?
           还是：地址1 + 命令1 + 数据2 + CRC2 = 6?
```

**正确的帧示例：**
```
发送：AA BB 00 06 02 01 00 10 xx xx CC DD
      ─────  ──  ─  ─  ────  ───  ────
      帧头   长度 地址 命令 数据  CRC   帧尾
              
分析：
- 帧头：AA BB (2B)
- 长度：00 06 (2B) = 6 = 地址(1) + 命令(1) + 数据(2) + CRC(2)
- 地址：02 (1B)
- 命令：01 (1B) = READ
- 数据：00 10 (2B) = 寄存器地址
- CRC：xx xx (2B)
- 帧尾：CC DD (2B)

总帧长 = 2 + 2 + 6 + 2 = 12字节
```

**接收响应：**
```
接收：AA BB 00 08 01 01 00 10 12 34 xx xx CC DD
      ─────  ──  ─  ─  ────  ────  ───  ────
      帧头   长度 地址 命令 数据   CRC   帧尾

分析：
- 长度：00 08 = 8 = 地址1 + 命令1 + 数据2 + CRC2
- 地址：01 (从机地址)
- 命令：01 (读响应)
- 数据：00 10 12 34 (寄存器地址 + 值)
- CRC：xx xx
```

## 4. 协议命令

### 4.1 命令码列表

| 命令 | 值 | 方向 | 数据格式 | 说明 |
|------|-----|------|----------|------|
| READ | 0x01 | Master→Slave | [寄存器高][寄存器低] | 读寄存器 |
| WRITE | 0x02 | Master→Slave | [寄存器高][寄存器低][数据...] | 写寄存器 |
| REPORT | 0x03 | Slave→Master | [事件码][数据...] | 主动上报 |
| HEARTBEAT | 0x04 | 双向 | 无 | 心跳保活 |
| ACK | 0x05 | 双向 | [原命令码][错误码] | 应答确认 |
| NACK | 0x06 | 双向 | [原命令码][错误码] | 应答否定 |
| RESET | 0x07 | Master→Slave | 无 | 设备复位 |
| UPDATE | 0x08 | Master→Slave | [块号][数据...] | 固件升级 |
| ERROR | 0xFF | Slave→Master | [错误码] | 错误响应 |

### 4.2 读寄存器 (READ)

**请求：**
```
AA BB 00 06 [ADDR] 01 [REG_H][REG_L] [CRC] CC DD
```

**响应：**
```
AA BB 00 08 [ADDR] 01 [REG_H][REG_L][VAL_H][VAL_L] [CRC] CC DD
```

### 4.3 写寄存器 (WRITE)

**请求：**
```
AA BB 00 0A [ADDR] 02 [REG_H][REG_L][VAL_H][VAL_L] [CRC] CC DD
```

**响应：**
```
AA BB 00 06 [ADDR] 02 [原命令=02][ERR_NONE] [CRC] CC DD
```

### 4.4 心跳 (HEARTBEAT)

**发送：**
```
AA BB 00 06 [ADDR] 04 [CRC] CC DD
```

**响应：**
```
AA BB 00 06 [ADDR] 04 [CRC] CC DD
```

### 4.5 应答 (ACK/NACK)

**ACK：**
```
AA BB 00 07 [ADDR] 05 [原命令][ERR_NONE] [CRC] CC DD
```

**NACK：**
```
AA BB 00 07 [ADDR] 06 [原命令][错误码] [CRC] CC DD
```

## 5. 错误码

| 错误码 | 值 | 说明 |
|--------|-----|------|
| ERR_NONE | 0x00 | 无错误，成功 |
| ERR_CRC | 0x01 | CRC校验失败 |
| ERR_LEN | 0x02 | 长度超出范围 |
| ERR_ADDR | 0x03 | 地址无效 |
| ERR_CMD | 0x04 | 命令不支持 |
| ERR_FRAME | 0x05 | 帧格式错误 |

| ERR_OVERFLOW | 0x07 | 缓冲区溢出 |
| ERR_BUSY | 0x08 | 设备忙 |
| ERR_PARAM | 0x09 | 参数错误 |

## 6. CRC校验

### 6.1 算法

- **算法：** CRC16-Modbus
- **多项式：** 0x8005
- **初始值：** 0xFFFF
- **校验范围：** 从"长度字段"到"数据域"结束（不含CRC本身）

### 6.2 CRC计算示例

```
帧: AA BB 00 06 02 01 00 10 xx xx CC DD
     ────────────────────────────────
     校验范围: 00 06 02 01 00 10

计算: crc16_modbus(00 06 02 01 00 10)
结果: 0x7A85

完整帧: AA BB 00 06 02 01 00 10 7A 85 CC DD
```

### 6.3 CRC参考值

| 数据 | CRC16-Modbus |
|------|--------------|
| 空 | 0x1D0F |
| 00 06 | 0xC6F8 |
| 00 06 02 | 0x8B7A |
| 00 06 02 01 | 0x5F25 |
| 00 06 02 01 00 | 0xE0B7 |
| 00 06 02 01 00 10 | 0x7A85 |

## 7. 地址规则

| 地址 | 说明 |
|------|------|
| 0x00 | 广播地址（仅Master发送，所有Slave监听） |
| 0x01 - 0xFE | 单播地址，指向特定从机 |
| 0xFF | 全播地址（所有从机响应） |

## 8. 通信流程

### 8.1 点对点通信

```
Master              Slave
   │                  │
   │──── READ ────────►│
   │                  │
   │◄─── ACK ─────────│
   │                  │
   │──── DATA (轮询) ─►│
   │◄─── ACK ─────────│
   │                  │
```

### 8.2 带重传的通信

```
Master              Slave
   │                  │
   │──── WRITE ───────►│ (t=0)
   │◄─── ACK ─────────│ (t=100ms) ✓
   │                  │
   │  (若超时200ms无ACK)
   │──── WRITE ───────►│ (t=300ms, retry=1)
   │◄─── ACK ─────────│ (t=400ms) ✓
   │                  │
```

### 8.3 心跳保活

```
Master              Slave
   │                  │
   │── HEARTBEAT ────►│ (每5秒)
   │◄─── ACK ─────────│
   │                  │
   │  (若60秒无通信)
   │── HEARTBEAT ────►│
   │◄─── NACK ─────────│ (设备离线)
   │                  │
```

## 9. 帧同步与错误处理

### 9.1 帧同步

协议使用固定帧头(0xAA 0xBB)和帧尾(0xCC 0xDD)进行帧同步：

1. 扫描字节流，定位0xAA
2. 验证下一字节是0xBB
3. 如果不是，继续从下一个位置搜索0xAA
4. 验证通过后，按状态机解析后续字段

### 9.2 错误处理策略

| 错误类型 | 处理方式 |
|----------|----------|
| 帧头错误 | 丢弃，搜索下一个0xAA |
| 长度超限 | 丢弃，重同步 |
| CRC错误 | 丢弃，记录日志 |
| 超时 | 重传（最多3次），超时后通知应用 |
| 缓冲区满 | 丢弃最旧数据 |

### 9.3 粘包处理

协议通过长度字段自动处理粘包：

```
原始字节流: [帧1][帧2][半帧3]
              │    │    │
              ▼    ▼    ▼
            解包 解包  等待更多数据
```

## 10. 传输层适配

### 10.1 支持的物理通道

| 通道 | 说明 | 典型应用 |
|------|------|----------|
| UART | 串口RS232/RS485 | 工业控制、传感器 |
| TCP | TCP客户端/服务端 | 网络通信 |
| UDP | UDP单播/广播 | 局域网发现 |
| CAN | CAN总线 | 汽车电子 |

### 10.2 传输要求

- **最小传输单元：** 1字节
- **字节序：** LSB优先（串口标准）
- **流控：** 需应用层处理（协议无流控机制）
